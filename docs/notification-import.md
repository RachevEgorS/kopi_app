# Подтверждение банковских операций · Android

Открой **Профиль → Уведомления банков** после входа в аккаунт.

1. Разреши чтение уведомлений в настройках Android и выбери банковские приложения.
2. Включи «Читать выбранные приложения».
3. Оставь включённым «Предлагать запись в уведомлении» и выключенным «Добавлять автоматически».
4. Нажми «Разрешить уведомления Копи». На Android 13+ это отдельное системное разрешение.
   Если показ запрещён в настройках телефона или канала, открой «Настройки показа уведомлений».

На новое распознанное уведомление банка Копи покажет предложение с суммой и категорией:

- **Добавить** — подтверждает запись без открытия приложения. Фоновая задача отправляет её в Supabase при наличии сети и действующей сессии.
- **Изменить** — открывает заполненную форму: сумма, вид, категория, название, дата. Сохранение подтверждает исправленную запись.
- **Пропустить** — удаляет предложение и сообщение из очереди.
- Смахивание ничего не записывает. Сообщение остаётся в очереди для ручной проверки.

До успешного ответа сервера показывается «Подтверждено · ожидает отправки». При сетевом сбое
Android повторяет попытку; скорость запуска фоновой задачи зависит от системы и энергосбережения.
Если короткоживущий токен входа истёк, нужно открыть Копи с интернетом: после обновления сессии
отправка возобновится. Фоновая служба не хранит refresh token, пароль или сервисный ключ.

Подтверждённые операции переживают перезапуск и не удаляются по сроку хранения очереди.
Они исчезают из очереди только после подтверждения сервером либо явного отключения чтения,
удаления выбранного банка, выхода/смены аккаунта. В последнем случае неотправленные записи
теряются — это отмечено рядом с переключателем чтения. Уже начатый запрос может успеть сохраниться.

## Распознавание и учёт

Распознаются однозначные рублёвые покупки, списания, зачисления и возвраты. Баланс отделяется
от суммы операции. Коды, реклама, отказы, будущие платежи, несколько сумм и неподдерживаемая
валюта не добавляются автоматически. Неизвестный формат можно открыть через «Изменить» в очереди.
Старые уведомления при подключении не сканируются. iOS и браузер не поддерживаются.

Автоматическое добавление — отдельный режим для расходов при открытом Копи. Доходы и возможные оплаты подписок требуют проверки.
Редактируемые и уже подтверждённые записи этот режим не трогает.

Одна банковская операция может приходить разными уведомлениями: их автоматической сверки нет.
Для возможной подписки кнопка «Проверить» открывает форму со связью с календарём. Единственный неоплаченный платёж с той же суммой в пределах трёх дней предлагается автоматически; пользователь подтверждает выбор. Связанный расход освобождает резерв, а повторная отметка той же оплаты не создаёт второй расход. Для дохода обязательно выбрать: новые деньги или уже учтено в начальном остатке. Оба случая сохраняются в истории.

## Хранение и проверки

- Не более 200 неподтверждённых сообщений; старше 48 часов удаляются при следующей обработке.
- После подтверждения сырой текст сразу удаляется; сохраняются только поля будущей операции.
- Суммы скрываются в публичной версии уведомления на заблокированном экране. Для кнопок нужен разблокированный телефон.
- Полный текст, баланс и реквизиты не отправляются в Supabase и не логируются. Android backup отключён.
- В базе используются source=notification, source_ref и постоянный UUID события: повторный запрос после сбоя не создаёт вторую запись.
- Для новой версии выполнить SQL-дополнение `202610300002_complete_diary.sql`. Сохраняются существующие ограничения доступа к данным владельца.

Проверки: Flutter-тесты; Android/JVM-тесты кнопок, смахивания, редактирования, повторов,
смены аккаунта, истечения сессии и повторной отправки после ошибки сервера.
Реальные форматы банков на телефоне ещё нужно проверить.

Основа: [Android notification actions](https://developer.android.com/develop/ui/views/notifications/build-notification),
[WorkManager](https://developer.android.com/jetpack/androidx/releases/work).
